# Recent Chat publication before archive catch-up

The existing conversation projection owner may expose a bounded,
non-authoritative recent lens before saved history, full database capture
and canonical indexing finish.
Provider records and the normal archive remain authoritative. The recent slot
is disposable memory owned by the actual agent runtime and Watch incarnation;
it never advances a persisted source frontier.

## Admission and retirement

The producer applies the existing capture policy to original native or normal
Watch identities before assigning preview IDs or clipping text. Unknown
timestamp/identity cutoffs fail closed. Disabled durable logging cannot
resurrect database history. A current fresh runtime may show its actually
observed LIVE messages after its recorded boundary, independently of durable
capture; a resumed external session cannot acquire that permission implicitly.

Privacy, clear, source, runtime and lifecycle boundaries retire admissions
before waiting for slow archive work. Late publications must match the actual
runtime/Watch handles and still-current admission issue. A failed publication
cannot erase a newer successful one. An unpublished slot cannot represent a
qualified empty window.

Watch observations use the normal provider extractor and original mapper
identity. Canonical Watch coverage also binds the exact transcript cursor,
because retained ordinals alone can reuse IDs. Gemini file-backed observations
come only from its normal completed-message parser with a matching session.
The receipt covers the actual descriptor identity, extent, modification time
and bounded first/last anchors. A changed file is withheld until normal parsing
binds another observation. This does not prove absence of an adversarial
in-place rewrite that also restores metadata and both anchors. Whole Gemini
JSON discovery or parsing is never added to selection reads.

OpenCode recent observations bind actual part, message, session, owned database
root/native identity and payload version. Antigravity uses the existing step
decoder and actual step identity/version. Neither adapter guesses a global
sequence or recomputes historical IDs from a truncated tail. The full producer
retains its established IDs, ordering, edits and persistence policy. Read-only
SQLite observations require a validated native-file guard; platforms without
that binding retain normal capture.

An edited OpenCode message may refresh its existing archive body only through
the actual full database capture receipt. That receipt binds the native file,
owned root, provider session, message, part and observed payload version. The
archive must already hold the same attested identity and prior version;
provider metadata or an unknown legacy binding cannot authorize replacement.
A changed database invalidates an older receipt. Current capture policy also
applies: a mutable part born before or inside a disabled interval cannot use
its creation time to authorize a replacement aggregate body.

Refresh preserves canonical IDs, narrative sequence and time, ordering and
delivery provenance. Existing materialization regenerates body references
while retaining old body artifacts unchanged. Event-first publication
failure is repaired through normal retry before canonical handoff. Canonical
Older and detail reads use their existing published proofs. A database body
or canonical head does not create framed SourceIndex renewal authority.

## Bounds and scheduling

Each slot holds at most 80 headers with at most 1 KiB of text per header and a
256 KiB serialized page budget. Total resident recent-slot data, identity and
control metadata is capped at 1 MiB and 512 slots plus headers/control entries.
Pressure evicts to a safe miss. No body artifacts, database connections or open
source handles remain in the slot.

A separate short mutex protects recent state. IO occurs outside it. Normal
desktop/PWA initial or latest demand can coalesce at most two producer jobs;
capacity remains held until the actual blocking job joins. The recent reader
does not wait for the full projection work lock. Existing per-domain physical
request ownership, visibility, scope and Older fairness remain in effect.

Database LIMIT clauses bound returned metadata only. Shared VM interrupts,
bounded payload reads and aggregate payload limits also bound attempted work.
Expensive/unindexed plans are misses, never evidence of fast publication.
Reported VM/logical payload costs do not measure physical disk IO or OS-cold
latency.

## Consumer and canonical handoff

The optional `recent_preview` request flag defaults false. Only normal initial
and latest reads may opt in. A non-null server-owned opaque `recent_admission`
marks a provisional window without canonical generation, file epoch, Older,
detail or renewal authority. Same-admission updates replace the bounded cohort;
changed or retired admission clears previous preview rows even if empty.
Malformed preview scope or boolean fields cannot qualify the window.

The reader leaves preview only when the actual published immutable canonical
head covers every cached native key and version under the same current scope.
Queued candidates, partial coverage and watermarks do not suffice. Native
identity lookup is an auxiliary index over real canonical rows, with a final
current-root membership check. An edit keeps the newer preview until capture
and publication catch up. Handoff resets the window without fabricated aliases.

Controlled provider fixtures, real read-only database tests and client tests
prove these boundaries at their respective layers. They do not establish
native UI paint latency, paid-provider behavior or cold-filesystem performance.
